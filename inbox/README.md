# inbox 收件箱 —— 任意环境 / 任意 AI 的快速写入通道

> 何时用：你所在的环境拿不到完整工具链（WorkBuddy 云电脑沙箱、网页版 AI、别人的电脑、
> 只装了 GitHub 连接器的会话），又需要把新事实沉淀进大脑。**唯一要求：能写 GitHub。**

## 写入规范

1. 路径：`inbox/YYYY-MM-DD-<简短主题>.md`（例：`inbox/2026-10-25-NAS迁移.md`）
2. 正文三段：**发生了什么 / 为什么（可选）/ 结论或待办**
3. 不确定归属哪个项目时写「待归类」，不要猜
4. inbox 只做**追加**，禁止在此修改既有档案

## 归档规则（由具备完整工具链的一端执行）

- 合并到对应 `projects/*.md` / `MEMORY.md` / `decisions/`
- 同步萃取进 Engram 语义层（项目按内容判断，不确定用「家庭网络运维」）
- 合并后删除 inbox 原文，commit message 注明去向

## 为什么这样设计

写入端不猜目标文件结构，避免写坏正式档案；inbox 是缓冲层。
A 层 GitHub 是唯一「所有 AI 都能写」的公共通道，Engram 是「有 MCP 时自动召回」的加速层。
