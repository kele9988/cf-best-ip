# 决策：Engram 语义记忆公网暴露方案（2026-10-25）

## 背景

需要在**手机 5G 外网**和**WorkBuddy 云电脑沙箱**（隔离环境、只有公网、无 MCP 连接器）下读写 Engram 语义记忆。
Engram 桥本身是 `INSECURE_NO_AUTH`（无任何鉴权），直接暴露等于记忆库公开。

## 备选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. Cloudflare 隧道 hostname + Access | 隧道加 `brain.kele9988.top → :18082`，套 Cloudflare Access 邮箱验证 | 域名自持、Access 是企业级鉴权、可审计 | 隧道为 token 模式，ingress 在 Zero Trust 面板；**本机 `cf_token` 无 Tunnel 权限（403）**，必须人工操作 |
| B. Tailscale Funnel + 自写 Bearer 代理 ✅ | Funnel 暴露 `:8443` → 自写代理 `:18083` 校验 Bearer → 转发 `:18082` | 全程命令行可完成、不依赖面板、可一键关闭、代理层可控 | Funnel 域名是 `*.ts.net`（不自持）；鉴权强度取决于 token 保管 |
| C. 仅 tailnet 内可达（不公网） | 只开 `tailscale serve`，手机装 Tailscale 客户端 | 暴露面最小 | 云电脑沙箱不在 tailnet，用不了；鸿蒙 Mate 90 装 Tailscale 需社区客户端 |

## 结论

**采用 B**，A 作为后续可选的长期升级路径。

实施三层：

1. `engram-mcp.service`：MCP 桥 `:18082`，带 `--project=家庭网络运维` 默认项目、autosync 双向 30s
2. `engram-proxy.service`：`/root/engram-cloud/engram_proxy.py` 监听 `:18083`，校验 `Authorization: Bearer` 后转发
3. Tailscale Funnel：`funnel --bg --https=8443 localhost:18083`（Funnel 仅允许 443/8443/10000，故选 8443）

公网入口：`https://fnnas.tailc9fc92.ts.net:8443/mcp`

## 原因与安全边界

- 记忆库默认无鉴权，因此**任何暴露方式之前必须先补鉴权层**——这是本决策的硬约束，不是可选项
- Bearer token 仅存于 NAS `/root/engram-cloud/proxy_token.txt`（600），**不写入任何记忆、文档或截图**
- 一键断网：`tailscale funnel --https=8443 off`（保留 serve 则退回 tailnet 内可达）
- 评估过的残余风险：Funnel 端点公网可扫、依赖 token 强度；若日后 `cf_token` 获得 Tunnel 权限，可迁移到方案 A 叠加 Access

## 附带决策：云电脑沙箱的写入通道

沙箱里无 MCP、无内网，但能写 GitHub → 设立 `inbox/` 收件箱作为**唯一可靠写回路**，
由具备完整工具链的一端归档（合并进正式档案 + 萃取进 Engram + 删除 inbox 原文）。
同时 `scripts/engram_http.py` 让沙箱在**持有 token 时**可直接读写语义层，不必绕 inbox。

## 回滚

- 关闭公网：`tailscale funnel --https=8443 off`
- 停代理：`systemctl stop engram-proxy`
- 桥保留（局域网内仍可用，无暴露）
